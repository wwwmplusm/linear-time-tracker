# Личный тайм-трекер для Linear

Приватный тайм-трекер с одним паролем владельца. По ссылке из Linear открывается выбранный проект или задача. Кнопка ▶ запускает личный таймер. Сайт и расширение показывают все запущенные и приостановленные таймеры в разделе **Активные таймеры**. Пауза замораживает отсчёт, а продолжение возобновляет его с того же значения. Команда **Запустить снова** в журнале начинает новый интервал по той же задаче. Журнал показывает последние 15 завершённых личных интервалов и 15 запусков агентов, каждый со своей длительностью.

## Конфигурация

Скопируйте [targets.example.toml](targets.example.toml) в `targets.toml` и укажите свои названия и постоянные `slug`. Один проект и две задачи могут выглядеть так:

```toml
timezone = "Europe/Moscow"

[[targets]]
slug = "project"
name = "Учебный проект"
kind = "project"

[[targets]]
slug = "issue-a"
name = "Задача A"
kind = "issue"

[[targets]]
slug = "issue-b"
name = "Задача B"
kind = "issue"
```

Адрес цели имеет вид `/t/<slug>`. Записи привязаны к `slug`, поэтому после добавления ссылок в Linear оставляйте его прежним. Если интеграция Linear не настроена, главная страница открывает первую цель из конфигурации. Часовой пояс определяет время в журнале и в форме «Записать запуск агента». Сервер сохраняет время в UTC. У каждого браузера отдельная сессия на 30 дней. Выход завершает текущую сессию, а смена пароля с перезапуском завершает все сессии.

## Локальный запуск

Нужны Python 3.11+ и `uv`. Следующие команды создают конфигурацию и пароль для первого запуска. Если `targets.toml` и `.env` уже настроены, используйте существующие файлы.

```bash
test -e targets.toml || cp targets.example.toml targets.toml
if test ! -e .env; then
  (umask 077; set -o noclobber
   printf 'TRACKER_DOMAIN=timer.example.com\nTRACKER_PASSWORD=%s\n' "$(openssl rand -hex 32)" > .env)
fi
uv sync --locked --no-dev
umask 077
TRACKER_SECURE_COOKIE=0 uv run --locked --no-dev uvicorn tracker.app:create_app \
  --factory --host 127.0.0.1 --port 8765 --env-file .env --no-access-log
```

Откройте `http://127.0.0.1:8765` и введите значение `TRACKER_PASSWORD` из локального файла `.env`. SQLite сохраняется в `data/tracker.sqlite3`. Для другого пути задайте `TRACKER_DB`.

## HTTPS для ноутбука и телефона

На постоянно доступном хосте с Docker Compose подготовьте те же `targets.toml` и `.env`. Укажите в `TRACKER_DOMAIN` собственное DNS-имя без протокола, направьте DNS на хост и откройте входящие TCP-порты 80 и 443. В `.env` нужен случайный пароль владельца длиной от 24 символов. Пример переменных есть в [.env.example](.env.example).

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail 50 caddy tracker
```

Caddy получает сертификат и перенаправляет HTTP на HTTPS. FastAPI доступен через Caddy, а порт приложения остаётся внутри сети Compose. Откройте `https://<ваш-домен>/t/project` на ноутбуке и на телефоне и войдите с одним паролем. Для работы по HTTPS Compose включает атрибут `Secure` у cookie. [Условия автоматического HTTPS в Caddy](https://caddyserver.com/docs/automatic-https)

SQLite хранится в именованном томе `tracker_data`, сертификаты — в `caddy_data`. Тома сохраняются при `docker compose restart` и обычном `docker compose down`. Команда `docker compose down -v` удаляет данные. При копировании базы для резервной копии сначала остановите приложение командой `docker compose stop tracker`.

Если Docker сообщает `all predefined address pools have been fully subnetted`, задайте свободную подсеть в отдельном файле Compose и добавьте его к команде через `docker compose -f compose.yaml -f <файл> up -d --build`. Пример для хоста, где `172.31.247.0/28` свободна:

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 172.31.247.0/28
```

## Ссылки в Linear

### Таймеры прямо в веб-версии Linear

Для Chromium или Chrome на ноутбуке установите расширение из папки `linear-extension`. В `chrome://extensions` включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите эту папку. После установки обновите страницу Linear. [Инструкция Chrome](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)

После обновления файлов расширения нажмите **↻** на его карточке в `chrome://extensions` и обновите вкладку Linear. Панель подскажет этот шаг, если Chromium использует старую версию расширения.

Войдите в трекер один раз в том же браузере через `http://localhost:8765` и подключите свой аккаунт Linear. На странице проекта кнопка **▶ По проекту** запускает таймер проекта. Чтобы запустить таймер отдельной задачи со страницы проекта, откройте **Таймеры и задачи** и нажмите **Запустить** рядом с ней. Открытая панель обновляет список при изменении вкладки **Issues**, при возврате в браузер и каждые пять секунд. В открытой карточке задачи есть кнопка **▶ По задаче** и форма **Записать запуск агента**. Активные интервалы и журнал доступны в панели.

Если трекер развёрнут по HTTPS, сохраните его адрес в параметрах расширения. Таймеры на телефоне можно открыть через веб-страницу трекера по этому же адресу. Панель расширения доступна в настольном браузере.

### Ссылки на веб-страницы трекера

1. Откройте проект → **Overview** → **Resources** → **+**. Добавьте `https://<ваш-домен>/t/project` и задайте подпись **Таймер**. [Документация Linear о ссылках проекта](https://linear.app/docs/projects#external-links)
2. В каждой задаче откройте меню **…** → **Add link**. Добавьте `https://<ваш-домен>/t/issue-a` или `https://<ваш-домен>/t/issue-b` и назовите ссылку **Таймер**. [Документация Linear о ссылках задачи](https://linear.app/developers/attachments)
3. Откройте ссылку. После входа трекер вернёт на выбранную цель. Чтобы начать работу, нажмите **▶ Запустить**.

### Приватное подключение Linear

В **Settings → Administration → API** создайте OAuth-приложение с выключенным переключателем **Public**. Для запуска на ноутбуке зарегистрируйте `http://localhost:8765/oauth/callback`. Для HTTPS добавьте `https://<ваш-домен>/oauth/callback`. Оставьте **Client credentials** и **Webhooks** выключенными. [OAuth в Linear](https://linear.app/developers/oauth-2-0-authentication)

В локальном файле `.env` с правами `600` задайте `LINEAR_CLIENT_ID`, `LINEAR_CLIENT_SECRET` и `LINEAR_REDIRECT_URI`. Значение `LINEAR_REDIRECT_URI` должно совпадать с зарегистрированным адресом. Для локального OAuth открывайте трекер через `http://localhost:8765`. OAuth-подключение хранится в той же SQLite. Запускайте один процесс сервиса, чтобы обновление токена выполнялось последовательно.

1. На главной странице трекера войдите, нажмите **Подключить Linear** и подтвердите доступ.
2. Откройте команду и выберите проект. Задачи, у которых нет проекта, доступны в разделе **Без проекта**.
3. Нажмите **Запустить** рядом с задачей. Таймер появится над списком задач. Нажмите **Остановить**, чтобы сохранить интервал в журнале.

Чтобы разместить ссылку на таймер в Linear, задайте в `.env` `LINEAR_TRACKER_ORIGIN=https://<ваш-домен>` и перезапустите или пересоздайте сервис. В разделе **Таймеры из Linear** появится действие **Добавить ссылку в Linear**.

## Проверки

```bash
uv sync --locked
uv run --locked playwright install chromium
uv run --locked pytest -q
```

Тесты создают две независимые сессии Chromium и временную SQLite. Они проверяют синхронизацию и сохранение старта после перезапуска, два одновременных запроса старта, повтор старта и стопа, а также длительности двух пересекающихся запусков агентов. Тесты используют системный `chromium`, если он доступен, или браузер Playwright. Путь можно задать через `TRACKER_TEST_CHROMIUM`.

Тест подключения Linear использует имитацию API и проверяет OAuth, переход от команды к задачам, запуск и остановку таймера, а также повторную публикацию ссылок.

Тест расширения загружает его в отдельном Chromium и проверяет запуск на задаче и проекте, синхронизацию со второй сессией, остановку и запись запуска агента.

## Исходное исследование

### Зачем

Владелец переносит работу в Linear, чтобы и он, и агент могли по проекту понять текущую цель, прогресс и следующий шаг. Команда в Linear соответствует сфере жизни, проект — конкретной задаче внутри сферы. У конечных проектов есть целевая дата, у долгосрочных, например работы с учеником, — майлстоуны текущих целей. Это желаемая структура. На момент первого обзора в пространстве было 6 команд и 12 проектов, у учеников уже были проекты, но ещё не было отдельных задач внутри них.

Нужен собственный бесплатный трекер с доступом из Linear и синхронизацией между устройствами. Timely и TrackingTime изучались как примеры. Подписка на их сервисы для работы собственного трекера не предполагается.

### Требования владельца

- Нажатие ▶ запускает личный таймер. Несколько задач могут идти параллельно. Запуск второй и остановка любой из них сохраняют состояние остальных.
- Один и тот же учёт доступен с ноутбука и телефона. Пользователь может начать работу на одном устройстве и закончить на другом.
- Время облачного агента учитывается отдельно от личного и относится к задаче Linear. Нужен факт запуска и его длительность. Параллельные запуски агентов на одной задаче различимы.

### Обсуждённые сценарии

- Урок можно начать из проекта ученика. Работу над конкретной задачей можно учитывать внутри её проекта. Способ размещения ▶ на разных клиентах Linear предстоит выбрать. В обзоре проекта Linear поддерживает ссылки и документы. Возможность добавить нативную кнопку в шапку проекта на всех устройствах пока не подтверждена. [Проекты Linear](https://linear.app/docs/projects) · [Публичный GraphQL API](https://linear.app/developers/graphql)
- Первый сквозной пример для проверки после начала разработки — запустить две задачи на ноутбуке, увидеть обе на телефоне, остановить одну и убедиться, что вторая продолжает идти.
- Предложение по отчёту — показывать длительность каждой задачи и отдельно время человека без двойного счёта пересечений. При 40 и 30 минутах по двум задачам с пересечением 10 минут это даст 60 минут личного времени за день. Правило итогов владелец отдельно не утверждал.
